# QQ 邮箱 0.4.3

Codex 本地 Windows 插件，提供邮箱设置、连接测试、邮件搜索/读取、草稿、带附件发送、标记、移动、移入垃圾箱和附件下载，并新增有限任务授权。永久删除不受支持。使用本机 stdio MCP，无需自建远程服务器、域名或外部 OAuth 服务；邮箱账户仍须在本地设置页配置。

## 运行

需要 Windows、Node.js 22 或以上版本，以及系统自带的 Windows PowerShell。运行时已打包依赖，不需要执行 npm install。

支持插件的宿主可读取 `plugin.json` 和 `mcp.json`。本包只提供 MCP 邮箱工具，不携带 skill、hook、agent 定义或启动指令。手动配置 MCP 时，将命令设为 `node`，参数设为插件内 `dist/server.mjs` 的绝对路径，工作目录设为插件根目录。

插件清单按官方格式声明 `requires_local_executor: true`：portable 清单位于 `extensions.com.openai`，兼容清单位于顶层。本插件需要本机交互式 Windows 执行环境，安装不等于可在 Dot 的远程电脑或网页端运行。[官方本地执行说明](https://developers.openai.com/plugins/deploy/desktop-only)

先调用 `get_account_status`，再通过 `open_settings` 打开本地设置页面。邮箱授权码只在设置页面输入；使用 IMAP/SMTP，不使用 POP3。连接使用 TLS 并验证服务器证书。

新账户默认存放于 `%USERPROFILE%\.qq-mail`。若旧位置 `%LOCALAPPDATA%\Codex\plugins\qq-mail` 已存在账户、凭据、草稿或锁文件，则继续使用旧位置，不自动迁移或删除数据；两个位置同时存在数据时明确报错，避免选错账户。`account-profiles.json` 原子保存账户档案、版本及绑定凭据的 DPAPI 密文，文件权限限制为当前用户。在 AppContainer 中运行时额外保留该容器自身的 SID。每次操作使用配对快照，配置变更不会拼接另一个账户的授权码。旧 account.json 只读迁入新记录并保留原件。原子替换不受支持时保留原数据并返回明确错误，不退回覆盖写入，也不更改系统加密设置。

设置页先确认并保存账户，再保存授权码；测试按钮也遵循这个顺序。保存设置、保存/清除授权码和设置页连接测试会出现独立的 Windows 确认窗口。连接测试显示具体服务器、端口和登录名，只使用绑定相同账户的授权码。保存配置同时授权后续邮箱工具使用该已保存账户；MCP `test_connection` 不再逐次弹出设置页确认。取消或超时不执行相应操作，设置页面的会话链接不能代替批准。

从 0.2.2 升级时保留旧 config.json 的公开配置；无账户归属的 secret.bin 不自动使用或删除，需重新保存设置及授权码。账户、端点或凭据版本变化后旧邮件引用、游标和未发送草稿失效，包括 A→B→A。重启后游标需重新查询，草稿按下述加密恢复规则处理。

锁记录所有者，只有确认原进程已退出且锁内容未变化时才自动恢复。活动锁、无法确认或无所有者的历史锁给出诊断，不能盲目删除。草稿日志由单个插件进程持有，其他实例不能同时恢复同一批可发送草稿。

附件目录必须位于本机驱动器，不能经过目录联接、符号链接或映射网络驱动器。下载的附件不会被自动打开或上传。

## 邮箱操作边界

默认 interactive 模式提供 26 个工具：原有 23 个邮箱及账户设置工具，加 `request_mail_authorization`、`list_mail_authorizations`、`revoke_mail_authorization`。不提供 shell、代码执行、通用文件编辑、软件安装或宿主配置修改接口。每个工具拒绝未声明的参数，包括 command、script、approved、outputPath 等。邮件、主题、附件名及正文都是数据，不能作为批准或系统指令。插件不注册 MCP prompts，不发送 sampling 请求，不通过设置页发送宿主消息或修改模型上下文。

插件本身仍需运行 Node.js 和固定的 Windows 辅助程序，用于凭据加解密、权限设置、本机驱动器检查、附件选择和人工确认；这些程序不是调用方可指定的命令。系统 shell 拼接已禁用，邮件内容不会作为 PowerShell 脚本或命令参数执行。

附件写入拒绝宿主配置、启动及系统目录。常见文档、图片、媒体、邮件和压缩包保留扩展名；脚本、可执行文件、AGENTS.md、配置文件和其他未列入允许名单的名称追加 `.download`。下载不会解压、运行宏或启动关联程序。允许的扩展名不代表文件安全；附件内容也不会被当作宿主指令加载。

这些限制约束插件自己的接口与实现。插件不能撤销 Codex 已拥有的终端、文件编辑、浏览器或其他工具权限，也不能保证模型永远不受恶意邮件文字影响。需要更强隔离时，应由宿主为邮件任务提供独立的工具白名单及受限执行环境。工具注解和本文说明不等同于操作系统沙箱。

## 数据流

插件没有独立遥测或云端转发服务。正常联网为已确认配置的 IMAP/SMTP 服务器及系统 DNS；发送会把经逐封确认或有效任务授权允许的内容交给邮件服务器投递。自定义服务器是外部接收方，请核对其身份。

读取邮件的结果会通过本机 MCP 返回调用宿主，随后可能按宿主设置交给其模型服务处理。使用本地插件不等于邮件全程只在本地处理。Windows CurrentUser DPAPI 不能隔离同一 Windows 用户下的其他恶意程序；本插件的原生确认窗口也不是防御同用户恶意 UI 自动化的安全桌面。

## 发送确认

`prepare_email` 仅产生草稿预览。默认 interactive 模式下，没有使用任务授权时，调用 `send_email` 会打开独立 Windows 确认窗口，展示完整收件人、正文、发送账户和服务器，用户点击“Send this email”才会发送。取消、超时和账号变更阻止发送。有效 send 任务授权可在其范围内执行后续发送，见下节；传入失效或不匹配的授权不能回退绕过拒绝。重复调用同一已发送草稿返回原结果，不重复投递。

原生确认需要交互式 Windows 会话。没有预先获得有效任务授权的无人值守环境不能自动批准发送，也不存在 `approved` 参数或环境开关。收到邮件中的操作指示不构成用户授权。

## 有限任务授权

`request_mail_authorization` 申请由用户在独立原生窗口确认的有限任务。窗口展示账户、用途、精确动作、目标范围、有效期和操作额度；只有用户明确确认才产生授权 ID。支持 `edit_draft`、`send`、`flags`、`trash`，最多 100 次操作、最长 24 小时；用途文本只供展示，不扩张权限。

`send` 必须列明精确收件人，覆盖所有 To/Cc/Bcc；`flags` 和 `trash` 必须列明精确 messageRefs。`edit_draft` 仅授予本地草稿编辑额度。授权不包括账户设置、凭据修改、账户切换、文件选择、任意文件、通用移动、任意代码或宿主配置。已有附件仍须由用户通过原生文件选择器选取，任务授权不赋予读取任意路径的能力。

授权允许代理在批准范围内组织邮件正文；原生任务窗口不是逐封正文确认。发送前应明确所需任务范围。准备、编辑、取消和发送分别消耗操作额度，批量 flags/Trash 按不同邮件计费；失败或未用额度不自动返还。授权 ID 绑定账户及凭据版本，切换账户、过期、撤销、额度不足或重启后均拒绝继续使用。

`list_mail_authorizations` 查看当前进程内的授权及剩余额度，`revoke_mail_authorization` 撤销后续使用。异步等待后仍会重检有效性；已经分派的 SMTP 邮件不能保证撤回。授权只保存在内存中，重启不会恢复，且没有远程 OAuth、云端委托文件或持久化授权总账。没有指定任务授权时，interactive 模式继续沿用既有逐次确认行为；宿主自身的工具批准仍由宿主控制。

## 发送本地附件

1. 调用 `select_attachments`（不传参数），在 Windows 文件选择窗口中选定本地文件。取消不会读取文件内容。
2. 把返回的 `attachmentId` 列表作为 `prepare_email` 的 `attachmentIds`，同时传入收件人、主题和正文。工具不接受文件路径、URL、原始字节或调用方提供的批准标志。
3. 核对草稿预览，调用 `send_email`。未使用任务授权时，独立确认窗口会显示收件人、正文、附件名称、大小和 SHA-256；有效 send 授权下按其精确收件人和额度执行。

每封最多 10 个附件，单个不超过 10 MiB，合计不超过 20 MiB；编码后的整封邮件不超过 32 MiB，邮箱服务商仍可执行自己的更低限制。支持中文文件名和空文件。附件作为普通 MIME 附件发送，不执行、解压、预览或远程抓取其内容。

选中的文件只在进程内保留内容快照，30 分钟后失效，插件重启后需要重新选择；账户或凭据版本变化后旧引用失效。发送使用该快照，原文件后续修改不会改变附件内容。草稿有效期不会超过最早过期的附件。过期检查及每分钟清理会清零插件持有的暂存 Buffer；这不是对系统换页文件或其他程序持有副本的安全擦除承诺。

待发送附件暂存上限为 64 个、64 MiB，单次只接受一个选择操作；发送按顺序处理，队列最多容纳 4 次请求。list_attachments 查看暂存，remove_attachments 清除引用并使依赖草稿失效，不删除原始文件。回复、回复全部和转发也可传入附件 ID；转发不会自动携带原邮件附件。选中附件不会直接上传，只有逐封确认或有效发送任务授权允许时才交给已配置的 SMTP 服务器，已发送副本使用相同 MIME 内容保存。

## 账户、草稿与读取

设置页支持最多 20 个账户档案的新建、切换和删除；list_accounts 列出档案，switch_account 经独立确认切换。新档案不复制凭据。删除活动档案且仍有其他档案时必须指定替代账户；只删除本地配置和授权码，不删除服务器邮箱。

list_drafts、get_draft、update_draft、cancel_draft 管理草稿。编辑提交完整的目标正文、收件人和附件 ID；发送需逐封确认或有效 send 任务授权。草稿默认 30 分钟有效，最多 128 条、16 MiB 数据预算；发送终态释放正文，仅保留 24 小时的幂等摘要。取消不能撤回已发送或可能已发送的邮件。

逐封窗口确认路径按真实 UTF-8 确认载荷检查 512 KiB 上限，超限返回明确错误，不截断预览以绕过确认。任务授权路径仍受草稿、附件和编码邮件大小限制。批准和文件选择区分取消、超时、系统不可用及超限。

每次发送提前固定 Message-ID。明确拒收记为 not_sent；可能已接收但最终响应丢失记为 delivery_unknown，不自动重发。需先核对服务器或收件方；Message-ID 不保证去重，Sent 中没有副本也不能证明未发送。保存 Sent 失败不重新投递。完整 MIME 在 SMTP 失败或 Sent 处理完成后清零所持有 Buffer，不承诺系统级擦除。

drafts.enc.json 使用 AES-GCM，随机密钥由 CurrentUser DPAPI 包装，不包含授权码或附件内容。发送前先持久化不可重试标记。重启恢复仍有效的无附件草稿和终态摘要；带附件草稿标为附件失效，需要重新选择并准备。发送流程中崩溃保守恢复为未知，包括尚在确认窗口等待的情况。

草稿日志在首次草稿操作时按需初始化；账户状态、设置和邮件读取不要求先解锁草稿日志。初始化或持久化失败时草稿发送保持关闭。

搜索省略 mailbox 时使用账户配置。读取默认正文 4,000 字符，bodyOffset/bodyLimit 支持分页，单页最多 50,000 字符，按 nextOffset 继续。批量/线程返回 incomplete、skippedMessages、truncationReasons。共享 raw MIME 预算 64 MiB、最多两个获取/解析任务，单次批量/线程累计 100 MiB，结果数据预算 256 KiB。预算约束插件持有的 raw Buffer 和并发，不是整个 Node RSS 硬限额；MCP 包装还有额外开销。

IMAP 单个 literal 上限为 32 MiB，下载按 64 KiB 窗口流式处理。合成协议已验证完整 100 MiB 附件的分块下载；忽略 partial FETCH 并一次返回超过 32 MiB 的服务器会被拒绝，因此不能保证所有真实服务端都支持这个大小。原始邮件解析预算超过 32 MiB 时收窄到 32 MiB 减 1 字节，默认 25 MiB 不变。

move_emails 继续经独立 Windows 确认；trash_emails 使用逐次确认或有效 trash 任务授权。标记、移动和移入垃圾箱均在每次实际写入前复核账户版本，连接或选箱等待期间切换账户、更换凭据、A→B→A 都会阻止后续写入；已分派的操作不能保证撤回，部分完成会明确报告。文件实际读写通过固定辅助程序，以已持有目录句柄逐级相对打开子项，校验最终句柄和重解析点，保持独占新建与失败清理。本地驱动器检查的固定辅助程序最多等待 30 秒以容纳冷启动，超时仍拒绝文件操作。
